# Adventurer A — direct 3D contact pair (shape-locked, unapproved)

**Decision stage:** the SD1.5 OpenPose and Depth variants were rejected as walk/contact art (see PR #1060 owner-PC GPU comments). Do not retry those conditioning workflows without a new hypothesis. This is the next *different* experiment: no AI redraws the hips, knees, boots or ground contact.

## What was actually made and tested

- Added `scripts/adventurer-a-walk/direct3d_contacts.py` to reuse the existing **actual 3D A/B meshes** from `prepare_pose_3d.py`. A source folder of existing `contact-a.glb` / `contact-b.glb` also works. It does not reconstruct a pixel cutout or interpolate warped source sprites.
- Adds **geometry** (not 2D paint) for dark trousers, brown shin-high leather boots, soles, buckled straps, dark split coat above the knee, tunic, sleeves, pouches, belt, charcoal hair and silver forelock. Reuses the rightward fixed camera azimuth -68°, elevation 23° and original two-leg IK contact positions.
- Renders the actual 3D surfaces with a CPU triangle z-buffer, flat material colors and restrained screen-space stippling; saves transparent 512x512 RGBA sprite **candidates**. For each pose, exports an inspectable, editable 3D `GLB` asset.
- QA images: `comparison.png` with two supporting ground shadows, and `phone-scale-qa.png` comparing both at 160px width, plus `qa.json` with foot-contact world coordinates and output hashes. The ground shadow is only in the review backgrounds; the candidate transparent PNGs contain just the geometry.
- World contact: **both A and B boot soles have world min Z = 0**, toes face +X. A camera-near leg is forward; B camera-far leg is forward. Same head and torso geometry, camera, projection and base colors. There is an unequivocal geometrical reversal, unlike the rejected AI redraws.
- Actual independent image and GLB exports were visually reviewed in the conversation. A local 2-test suite passed: grounded reversal and rendered transparent output, different A/B hashes, 3D costume export and fail-on-overwrite. Repo CI additionally tests via `test/test_adventurer_direct3d_contacts.py`, with optional 3D dependencies skipped if unavailable.

## Reproduce

Use a separate Python with `numpy trimesh Pillow` — for example the already provisioned `pose-depth-venv` on the owner Windows machine. No GPU, new model download or paid API is required.

From an up-to-date checkout of PR #1060:

```powershell
& 'I:\02_AI\ComfyUI-Crownless\pose-depth-venv\Scripts\python.exe' scripts/adventurer-a-walk/direct3d_contacts.py --out 'I:\02_AI\ComfyUI-Crownless\direct3d-contact-review-v1'
```

Output directory must be absent or empty; repeat tests in a **different fresh destination** only when necessary, to avoid accidental overwrites. If using previously generated real A/B GLB meshes instead of source code, pass `--source 'FOLDER_CONTAINING_CONTACT_A_AND_B_GLB'`.

## Human visual verdict (this prototype)

**Mechanics: PASS; art: NOT APPROVED.**

Both contact poses visibly alternate. Both 3D boot soles remain grounded; the transparent frame silhouettes preserve exactly the authored mesh positions. The candidate also inherits the historical approved idea of counter-swinging arms. This establishes that the **pose itself need not be regenerated by AI**.

However the blockout is too angular and mannequin-like at phone scale. The trousers/knees and coat opening need anatomical/material refinement; the light ivory chest patch and head silhouette only loosely evoke the approved Adventurer A anchor. It does **not** pass the Canon requirements for rich irregular pixel art, tiny restrained face and authentic identity. Two contact frames are not a validated 8-frame looping walk.

**Next smallest useful test:** preserve the exact 3D silhouette/boot grounding; apply only texture/material finishing to the *inside* of the rendered geometry. If a generative model creates texture color, mask/composite it inside the exported RGBA silhouette so it cannot move the legs, soles or camera. Compare the rendered pair at 128–160px and only then decide whether more character modeling is justified. Do not auto-accept, merge, deploy, build eight frames, or overwrite the approved identity and other protagonists.


## Next texture-only safeguard implemented (no new AI image claimed)

Added `scripts/adventurer-a-walk/finish_direct3d_material.py` with regression test `test/test_adventurer_direct3d_material_finish.py`. A future locally AI-generated **512x512 texture candidate** can be supplied as `--paint`, while the approved-for-study 3D transparent candidate is `--geometry`. The compositor transfers a *bounded luminance variation only* and forcibly reuses the **exact 3D RGBA alpha**. Consequently, a generated candidate **cannot physically relocate a boot, change the silhouette, or recolor the indigo/boot palette into another identity**; exterior pixels are transparent. It refuses output overwrite and any unsupported image size.

Example only after a texture candidate exists:

```powershell
python scripts/adventurer-a-walk/finish_direct3d_material.py --geometry 'pose-a-direct3d.png' --paint 'future-ai-texture-a.png' --out 'pose-a-finished-review.png'
```

This is a constrained material prototype, not proof the candidate is artistically coherent. It cannot fix the current mannequin anatomy or magically produce approved pixel art. No new generative texture images or GPU workflows were run in this step.
