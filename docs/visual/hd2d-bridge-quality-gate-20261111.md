# 石橋の HD-2D 品質ゲート（候補、未採用）

## 対象

- **実際に動く画面**: `gemini-feel-lab.html?art=bridge`。
- **比較基準**: `gemini-feel-lab.html`（現行ドット絵）と `?art=classic`（旧描画）。
- **基準素材**: `assets/action-forest/bridge-hd2d-candidate-v1.webp`。
- **保持するもの**: 既存の地形高低差、キャラ操作、戦闘、祠・足跡の発見、収集、生還、鍛冶、セーブ。
- **変更箇所**: 背景、近景遮蔽、間景の薄い霧だけ。ゲームロジックは変更しない。

## ビジュアルの狙い

単に絵の綺麗さを比較しない。和紙＋墨の世界観と承認済みドットキャラを維持しながら、
石橋・谷・古城を一目で見分けられ、**歩いたときに絵と遊びが一致するか**を検証する。
生成背景は候補であり、実プレイで認められるまで Visual Canon に昇格させない。

## 390px / 360px 実プレイ確認項目

1. 遠景・石橋・キャラの奥行き、足元の着地点、接地影が一致している。
2. 橋を左右に歩いたとき、背景と手前の石・木の遮蔽が不自然に滑らない。
3. 祠と足跡が霞や近景で隠されず、指で操作できる。
4. 戦闘の敵・味方・攻撃予兆が埋もれず、ボタンも既存通り使える。
5. 帰還・素材確定・鍛冶・再出発に画風変更の副作用がない。
6. 実機で著しいフレーム低下、ロード失敗、白画面がない。

## 明確な未完了点

- この候補は立体形状で再構築されたフル 3D 地形ではない。
- 現行世界の当たり判定は旧来の橋の曲線で、絵の石積みとは完全一致していない可能性がある。
- 生成画像の遠近法が移動・カメラに追従しても自然に見えるかは、実機スクリーンショットと操作で判断する。
- クオリティ基準に達しなければ画像の採用・本編マージをしない。

## 判定欄

- プレイヤー評価: 未実施。
- 採用可否: 保留。

## 2026-11-12 奥行き再検証（別モード）

ユーザーから前候補について「キャラは浮いている」「奥行きがなく一枚絵」と評価された。
`?art=bridge` は比較用に残し、`?art=depth` を別の実験として追加する。

- 奥の山・城のみ旧画像から切り出し、カメラ移動量の12%で視差移動する。
- 橋の床と側面をゲームの `getGroundHeightAt` と同じ高さから、多角形メッシュとして投影する。
- 遠い石・床・欄干を縮小し、手前の欄干は人物と同じZ順に描いて実際に隠れるようにする。
- キャラ、敵、ドロップ、祠・痕跡の見た目とタップ判定を同一の遠近変換に合わせる。
- 足元の落ち影を地面投影点に置く（ジャンプ時は薄くする）。
- 戦闘・探索・収集・帰還・鍛冶・セーブ・コライダーは変更しない。

今回のレンダラは軽量な Canvas 2D による立体面の投影であり、フル3Dエンジンではない。
「動くと奥行きがわかるか」の視覚テスト用。高品質な背景・キャラの最終採用候補ではない。
比較モードの実画面とスマホ操作を確認するまでは `main` にマージしない。

## 2026-11-13 新目標：古城と滝の独立した奥行きレイヤー

ユーザーが提示した夕景の古城・滝・石橋・小さなドット絵パーティの参考画を、新しい探索フィールドの目標とする（#1114 / Visual Canon変更PR #1115）。旧「和紙＋墨」指定よりも、この**探索フィールド限定**の新しいユーザー指示を優先する。ただし参照画のコピー1枚を背景に貼るだけでは合格しない。

- **新しい比較モード**: `gemini-feel-lab.html?art=vista`。既存 `?art=bridge` と `?art=depth` は残す。既定の `gemini-feel-lab.html` と本編 `expedition.html` は変更しない。
- **素材は3ファイルに分離**: `vista-castle.svg`（古城・崖）、`vista-canyon.svg`（峡谷・滝・霧）、`vista-canopy.svg`（前景の樹木）。
- **視差**: 城14%、峡谷32%、手前樹木70%の異なるカメラ移動割合。実際の歩行可能な橋・物理投影・足元・タップ判定・手前欄干のZソートは `src/hd2d-bridge-depth.js` を共有。
- **負荷・互換**: SVGはオプトインモードでだけ読み込む。現実GPS、セーブ形式、アイテム、戦闘・製作は変更しない。Canvas2Dで試してから技術選択する。
- **検証**: `test/hd2d-bridge-vista.test.js` でレイヤー/投影差と旧モード維持を確認。CIで `scripts/verify-castle-vista.cjs` を実ブラウザ起動し360/390/430縦・844横の描画・移動とスクリーンショットを検査する。

**重要**: これは手描きSVGベースの構図・レイヤー検証用試作であり、ユーザー画像と同等のアセット品質を達成したとは主張しない。最初のブラウザテストは描画成立待ちでタイムアウト。現在、未読込のアセット名・ページエラー・実描画回数をCIに出力する診断を追加して調査中。既存機能の改善と新しい背景の視覚評価は分離し、両方の確認が完了するまで `main` へマージしない。
